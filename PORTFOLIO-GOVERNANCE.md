# Portfolio Governance Baseline

This document defines how GitHub activity should support Devina Azaria's academic, engineering, and creative portfolio.

## Objective

GitHub should show a credible learning history, not an artificial activity graph.

The portfolio should make it possible to answer:

- What problem was being worked on?
- What did Devina personally understand or contribute?
- What tools or methods were used?
- What changed as a result?
- What evidence exists?
- What did Devina learn or reflect on afterward?

## Repository Boundaries

### Personal repositories

Repositories under `DevinaAzaria/*` are for personal portfolio work, experiments, learning projects, and public evidence.

`devina.id` is the canonical personal portfolio.

### Organization repositories

Repositories under `DevinaHQ/*` are organization or collaborative projects. Devina may contribute when the work is genuinely connected to her learning, projects, music, research, or portfolio.

Meaningful organization contributions should preferably use issues and pull requests so the contribution has context and review history.

## Authenticity Rule

A contribution should only be presented as Devina's work when she can explain:

1. the goal,
2. the relevant files or concepts,
3. what changed,
4. why the change was made,
5. the result or limitation.

AI-assisted work is acceptable as part of the workflow, but the portfolio should not imply independent authorship of work Devina cannot explain.

## Project Documentation Standard

Use this sequence whenever practical:

**Problem → Process → Tools → Result → Evidence → Reflection**

Evidence may include code, screenshots, data, competition results, notes, recordings, design iterations, or links to deployed work.

## Contribution Quality

Prefer:

- a small number of coherent projects,
- descriptive commits,
- issues that explain intent,
- pull requests for meaningful collaborative changes,
- README files with evidence and reflection,
- steady long-term progress.

Avoid:

- empty or unexplained repositories,
- meaningless commit streaks,
- large imported projects without attribution or context,
- claiming work that cannot be personally explained.

## Portfolio Narrative

The primary academic narrative is:

**Science → Engineering → Aerospace**

Supporting dimensions can include astronomy, coding, music, culture, leadership, and creative technology when they demonstrate learning, discipline, experimentation, or multidisciplinary capability.

## Review Cadence

Review the GitHub portfolio at least once per academic term:

- archive or hide low-value experiments,
- identify 2–4 strongest projects,
- ensure evidence is preserved,
- improve README and reflection quality,
- link selected work back to `devina.id`,
- verify public claims remain accurate.
